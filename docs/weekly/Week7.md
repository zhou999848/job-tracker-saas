配置问题 * **问题一：项目无法识别为 Java 项目** 在创建 Java 类时（Day 5）发现 IntelliJ 无法识别该项目为 Java 项目，提示结构不合法。 * **问题二：GitHub Actions 无法启动工作流** 在设置 GitHub CI 工作流（Day 4）时，发现 Action 无法启动，报错提示根目录中找不到 pom.xml 文件。 * **解决方法**： 将原先创建在 jobtracker 文件夹中的所有内容（包括 pom.xml、src 目录等）整体移动到项目根目录下。此操作完成后，IntelliJ 项目标识的右下角出现蓝色小方框，表示项目已被正确识别为 Maven 项目。随后重新提交 .github/workflows/ci.yml 到 GitHub，CI 工作流成功启动并显示绿色对号，问题解决。 --- ### 💾 第二周：数据库连接问题 * **问题：使用 Postman 测试保存和读取 Job 信息失败** 在实现 Job 的保存与查询功能（Day 2）时，使用 Postman 测试接口失败，Spring Boot 控制台报错提示无法连接数据库。 * **解决方法**： 在 application.properties 中正确配置 PostgreSQL 数据库信息（包含数据库名、用户名、密码），并在 pom.xml 中加入 PostgreSQL JDBC 依赖。刷新 Maven 后，控制台成功输出 Tomcat started on port(s): 8080，表示数据库连接与服务启动正常，问题解决。 --- ### 📎 第三周：Note 与 Job 的关联与附件上传下载问题 * **问题一：浏览器点击 Job 无法显示对应的 Note 信息** 在 Day 5 测试时发现，浏览器中点击某个 Job 条目后，跳转页面看不到我事先提交的 Note 内容。 * **解决方法**： 原因是 Job 和 Note 之间没有正确关联。通过 Postman 手动提交一条 Job 数据并获取其主键 ID，然后在提交 Note 时确保其 jobId 与该 Job 的 ID 一致。这样点击 Job 即可正确显示关联的 Note 信息。 * **问题二：Note 中无法显示附件信息** Note 创建成功后，前端页面上无法显示与之相关的附件。 * **解决方法**： 使用 Day 4 和 Day 5 学到的 uploadMulti 接口，在上传 Note 时确保请求路径和参数格式正确（包含 Note ID 和多个附件文件），提交成功后，浏览器页面成功展示附件下载链接。 * **问题三：点击附件链接后无法下载文件** 点击附件链接时页面报错，文件无法下载查看。 * **解决方法**： 复用 Day 3 实现的 download 接口，并在 note.html 中修正附件链接地址，使其正确指向 /api/notes/download/{filename}。验证后，点击附件链接可成功下载并查看 PDF 或图片文件。 * **最终结果**： 在浏览器中点击某个 Job 时，可查看对应 Note 内容及其上传的多个附件，点击附件名称即可下载对应文件，功能完整闭环。 --- ### 🔐 第四周：登录认证功能问题 * **问题：Postman 调用登录接口返回 401 Unauthorized** 在实现登录功能（Day 2）时，Postman 请求总是返回 401 错误，无法获取 token。 * **解决方法**： 1. 将 UserController 中多个构造函数合并为一个，确保依赖注入正常； 2. 使用 DBeaver 检查数据库中是否已成功注册用户； 3. 在 UserService 中更改密码加密方式，确保密码存储与验证一致； 4. 在登录接口中添加异常处理，打印详细错误信息； 5. 修正 JwtUtil 中 SecretKey 的生成逻辑，确保 JWT 编码/解码一致； 6. 最终重新测试，成功返回包含 token 的 JSON 响应，状态码为 200 OK，认证功能验证通过。 ## 📈 总结收获 * 熟悉 Spring Boot 后端开发流程 *
