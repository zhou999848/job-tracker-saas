## 1. 完成した機能

### ✅ 第7週：マルチテナント基盤 & 管理機能
- `Tenant` エンティティ設計（User ↔ Tenant 関連付け）
- Job / Note 等のエンティティに `tenant_id` カラム追加、全クエリにテナントフィルタ適用
- `TenantContextHolder` 実装（リクエストごとのテナント情報保持）
- JWT に `tenantId` と `role` を埋め込み、フィルタで SecurityContext に設定
- 3種類のロール導入：`USER / TENANT_ADMIN / SYSTEM_ADMIN`
- **テナント管理機能**
    - 招待リンクによるメンバー招待・参加
    - メンバー削除（最後の管理者保護あり）
    - 権限変更（USER ↔ TENANT_ADMIN）
    - テナント名変更（TenantAdmin権限）
- **システム管理機能**
    - SYSTEM_ADMIN が全テナント一覧表示
    - テナント作成 / 停止（suspend） / 再開（resume）
- 最小限の Thymeleaf UI（メンバー一覧・招待フォーム・テナント情報ページ）
- API 自測（Postman/HTTPie）とスクリーンショットドキュメント化

## 2. 発生した問題と解決策

### 🔐 最後の管理者削除
- **問題**: テナント内の管理者を全員削除できてしまい、誰も管理できなくなる
- **解決策**: Service 層で「管理者が1人だけなら削除不可」という不変条件チェックを追加

---

### 🧩 役割変更時の自己降格
- **問題**: 管理者が自分自身を USER に降格でき、テナントが「無管理状態」になる
- **解決策**: Service 層で「自分自身の降格は不可」というチェックを追加

---

### 🚫 テナント停止（suspend）後の挙動
- **問題**: テナントを停止してもユーザーが書き込みできてしまう
- **解決策**: `TenantGuard.ensureTenantActive()` を全 Service 書き込み操作に適用、停止中は `AccessDeniedException` を投げるよう修正
